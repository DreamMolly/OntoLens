# OntoLens 竞赛质量规划

项目目标是形成有竞争力的华为 ICT 创新赛作品。赛题要求与来源见[来源核对](11-sources.md)，当前完成状态见[里程碑](37-teammate-handoff.md)。功能数量、界面美观或合成测试分数不能对应获奖等级。

## 评审可以看到的主线

一条申请从台账与制度出发，经过版本发布、核验、证据回查、补件复核，最终导出并独立重算。Nexent 组织工具与 Skill，模型辅助找到证据和解释，程序拥有决定权。

| 方向 | 当前工程基础 | 继续验证 |
| --- | --- | --- |
| MCP / Skill | 七工具、三项职责 Skill、独立解释实例 | 当前平台完整运行、失败恢复与独立环境复现 |
| 数据资产业务价值 | 六类来源、原字节/定位、公开制度包 | 真实授权台账、业务任务与节省的工作量 |
| 低资源本体方法 | observed / proposed 候选、版本与变更预览 | 相同人工预算下的基线对照、领域标签与错误分析 |
| 交互与能力沉淀 | D1.1 工作台、完整来源链、部署与导出 | 真实设备、读屏、任务效率与可复用模板 |

## 方法评测

研究“按受影响决定安排候选审核”是否优于人工字段表、普通检索、固定本体或全量重建。在实验前固定资料划分、候选预算和评价协议，不读取最终测试标签排序。确定性判定器是所有方案的共同基础。

主要结果应报告正确修复数、误改数、错误放行、误拒、人工耗时、调用成本和延迟。合成反事实与规则留出用于工程回归，独立行业结果另报。

## 展示体验

首页和表单让评委迅速理解任务，原文与关系在同一屏可回查。演示要包含缺件、超时、过期批次、版本冲突与恢复，不展示假 KPI、假保存或固定文字冒充实时模型。复杂度通过渐进展开控制，完整代码和复现入口保持可查。

## 未完成条件

授权资料与领域适用核验、独立人工标签、方法收益、跨机器冷启动、长期稳定性及正式提交均需实际证据。不得虚构试点、专家认可、法规认证或原创性。准备材料与代码讲解时，以可核对的来源与失败边界回答问题。
