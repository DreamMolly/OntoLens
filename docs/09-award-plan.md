# 冲奖版规划

日期：2026-09-22。状态：重新规划，尚未实现。用户要求重新审视国奖竞争力，本文件取代此前“演示完成后等待至 2026-11-10”的推进安排。目标是形成有竞争力的中国总决赛作品；没有依据把某项功能或样本量直接对应到获奖等级。

本轮只修订规划；现有规则、案例和程序保持原样。官网要求与同类开源证据见 [来源核对](11-sources.md)，研究假设见 [研究问题卡](10-research-question-card.md)。

审查结论：完整冲奖立项暂不合格，只进入有退出条件的小规模验证。硬缺口、人员投入与资源见 [规划审查](14-plan-review.md)；执行日期以 [日程](06-schedule.md) 为准。以下完整功能属于通过前置检查后的预案，不把写完文档当作验收通过。

## 先纠正赛题理解

- 官网当前赛题 3 初赛四项各占 25%：MCP/Skill 深度集成、数据资产业务价值、低资源本体算法创新、交互与能力沉淀。
- 中国总决赛技术评分 60%（上述四项各 15%），答辩评分 40%（展示与问答各 20%）；另列附加分 10 分，涉及多行业模板迁移和真实脱敏行业数据评测。附加分不是已经获得的成绩，也不自行推断总分封顶算法。
- 赛题 3 只有初赛和中国总决赛，国赛线上答辩 15 分钟展示、5 分钟问答。此前安排赛题 3 全球总决赛不正确。
- 赛题 3 国赛一、二、三等奖最高名额分别为 4、6、8；组委会可根据成绩调整实际名额，晋级不等于自动获奖。
- Nexent 可以本地下载开发。此前把华为账号当作本地安装的必备前提不准确；部署仍需要队员落实机器、模型服务与授权。

这些来自 2026-09-22 读取的华为赛事页，不是套用赛题 1/2 或上一届规则。

## 先看现实差距

现有 v1、v2、v3、60 条案例和升版门禁证明了教学原型在已知输入上的行为。它们没有证明行业安全性、AI 学习能力或国奖竞争力：v2 的改动是预先写好的开关，当前 promote 只给出检查报告，不实际发布版本；Nexent 尚未运行；申请中的当天领用类别由调用方提供，没有对接可信领用事件。

官方赛题 3 要求多模态异构数据资产认知、低资源领域知识图谱本体半自动构建、Nexent MCP/Skills 编排、跨文档多跳推理、决策溯源和可复用模板。旧计划缺少其中的大部分内容。

建议新定位为：

> 配伍：面向制造业研发实验室的可进化合规资产认知与领用决策智能体

“配伍”仍是项目名，实验室危化品领用仍是演示场景。制造业研发实验室目前只是待验证的目标用户，不能把校园合成目录改个名字就写成企业场景。首个现实任务是找得到资料的研发实验室：在批准前核对批次、人员授权、柜位与当前制度，并回溯依据。首轮只做历史回放或旁路审核，不实际出库。

| --- | --- | --- |
| 保留原来的规则 CLI | 可保留为测试基线，参赛证据不足 | 不再据此许诺国奖 |
| 配伍升级为行业资产认知与变更审核 | 首选验证路线，复用已有判定逻辑 | 两周内有资料、业务人员审核和平台资源，2026-10-12 前验证真实 Nexent 调用 |

## 核心研究问题

在低资源的制造业研发实验室合规场景中，按决定影响安排本体候选复核，能否在相同人工预算下比人工字段表、文档检索、固定本体或全量重建正确修复更多受影响问题？确定性判定器是共同基础，不能单靠它击败弱对照来证明方法创新。

作品只声称可验证的工程贡献：同一条申请的最终安全决定由程序产生；模型负责从异构资料中找证据、提出结构化候选和生成解释；候选规则必须经过回归、事故和留出门禁。是否优于基线，必须由固定数据和外部评测证明。

## 只押一个主要技术贡献

拟验证“按受影响决定优先安排人工复核的本体增量修订”。本体指系统认识哪些对象和关系，不是把事实多录几条；增加一条库存记录属于事实更新，新增一种有明确制度依据的资格有效期关系才可能涉及本体更新。

具体流程：

1. 冻结一份专家审核的初始 schema，从新文档抽取带原文定位的类型/关系定义候选；schema 候选与别名、实例事实分开。5/10/20 指可审核候选预算，初始种子规模另记；候选不足就报告实际数量。
2. 用现有本体类型、关系端点、单位和生效时间检查候选，标出别名误合并、制度新旧冲突、缺失来源等问题。
3. 在不发布的沙盒中记录候选对开发问题路径的影响，按来源冲突、受影响路径数、关系覆盖、稳定 ID 排序，并限制重复关系族占用。具体公平对照和主指标见 [评测协议](13-evaluation-protocol.md)，排序不得读取最终测试标签。
4. 同样人工审核预算下，对比随机抽样和普通不确定性抽样，测本体修订正确率、人工耗时和后续跨文档决定的正确率。
5. 审核通过后生成带版本的图谱；只重算受影响路径，并与全量重算比较结果一致性和工作量。缓存加速不能单独宣传为原创算法。

这是工程研究假设，尚未证明学术原创。GraphRAG、LLM 本体生成和 SHACL 校验都已有开源实现；项目贡献必须体现为自己的选择策略、变更数据与实验优势。若普通表连接加人工规则同样快且准确，应承认图谱收益不足并缩小方案。

法律、正式制度和专业安全限制不能由反馈自动放宽。模型可建议别名、关系和证据映射；安全规则变更需明确权威来源和负责人审核。坏候选被拒绝不等于系统完成了自主学习。

## 作品架构

数据流：

    PDF / 表格 / 扫描图 / 制度文档
                    ↓
    文档解析与证据账本
      文档、页码、表格单元格、原文片段、来源版本
                    ↓
    低资源本体候选 + 实体关系图谱
      化学品、危害类别、批次、位置、人员、制度、限制、申请
                    ↓
    Nexent 检索 Skill + 图谱推理 Skill
                    ↓
    MCP：证据检索 / 图谱查询 / 配伍判定与升版门禁
                    ↓
    ALLOW / DENY / LIMIT / ISOLATE
      决定 JSON、证据链、图谱路径、规则版本、审计记录

Nexent 不直接决定是否放行。任何自然语言解释都必须能回到决定 JSON、证据片段和规则版本。规则内核继续使用 decide、eval、promote 三个命令；新 MCP 适配层的接口在架构文档先定义，再建设。真正的知识版本发布、回滚和审计目前均未实现。

资产导入 Skill 负责解析与待审候选；申请核验 Skill 负责检索、图查询和调用决定程序；变更复核 Skill 负责变更影响报告、校验及版本对比。库存、批次和人员权限来自可信数据快照，不接受申请人的自由文本作为最终事实。资料不完整、来源冲突或工具失败时进入人工复核，不能让模型补出放行决定。模型提取错误能穿过确定性程序，所以必须测全链路，而非只测 checker。

## 数据和知识图谱

第一版只收集能支撑演示和评测的资料，不追求大而空的知识库：

- 化学品安全数据表或公开安全说明的 PDF，作为名称、危害类别、储存限制的来源。
- 库存和批次表格，作为实体、状态、库存量和位置的来源。
- 学校或单位的领用、存放、培训和审批制度文档，作为业务规则来源。
- 检查记录、事故复盘或明确标为合成的事件文档，作为变更来源；合成事件不能称作脱敏真实事件。

每一条图谱事实都要保存 source_id、原始文件哈希、文档版本、生效区间、页码/单元格/图片框、原文片段、抽取器版本和审核状态。模型置信度只能作提示。公开不等于允许重新发布，来源登记需写明可读、可处理和可开源范围。扫描件须包含实际影响决定的表格或标识，并测试误读；只给纯文本套一层图片不算多模态贡献。

首轮统一为至少 6 份源文件、2 个开发资料包和 10 个问题，至少包含一个前后版本变化及一个影响结论的图像/表格字段。先核验关联性与标注质量，才能考虑约 30 个资料包的正式实验；文件数、问题数和独立来源数分别报告，不规定必须凑到某个数量。按来源家族和版本血缘分组，依据实际资料条件锁定开发/验证/盲测清单。领域人员核对金标准，另一名队员复核歧义。

现有 H01–H60 已被开发者反复查看，虽然未据此改 v2，也只能作为冻结的合成回归基准，不能再当作独立行业盲测。它们原文件、名字和规则卡保持不变。新本体任务单独评测，不继续灌充 H 集；最终盲测封存，开发期门禁只用开发/验证资料。

本体最小闭环只保留以下实体和关系：

- 实体：Chemical、HazardClass、Lot、StorageZone、Person、Policy、Request、Decision、Evidence、RuleVersion。
- 关系：化学品属于危害类别、批次对应化学品、批次位于位置、人员具备授权、制度约束类别或位置、申请引用批次、决定由规则版本产生、事实由证据支持。

## 算法和评测

不能用模型自报准确率。字段和关系指标基于人工审核标签，计时和调用成本基于执行日志。三名非开发者只用于小规模可用性试验，不能据此宣称大规模效果。

### 对照系统与公平比较

1. 人工整理字段 + 表连接 + 静态规则：最重要的非 AI 对照，记录维护制度变更所需的时间。
2. 文档检索增强 + 同一个判定内核：使用相同模型、资料、提示预算和输出结构，区别只在取证方式。
3. 固定本体图检索 + 同一个判定内核：检验增量本体修订是否有额外作用。
4. 配伍完整方案：按决定影响选择审核候选，更新证据和图谱，再调用同一个内核。

正式实验再加入全量本体重建 + 相同审核预算，防止只比较无法应对变化的静态方案。方法实验与原文端到端实验分开，人工整理好的正确字段不能充作自动抽取能力。

直接问模型可作为补充演示，但不能只赢一个没有规则保护的弱基线就声称算法优越。每项比较保持模型版本、来源范围和人工预算一致；模型抽取重复运行至少 3 次，记录失败、延迟和成本，不只挑最好一次。

### 必须记录的指标

- 结构化抽取：在人工标注的实体、关系和字段集上报告字段准确率、关系 Precision/Recall/F1，并标明样本数。
- 证据支撑：答案中每个关键事实是否能定位到来源文档、页码或单元格；报告证据覆盖率和无依据断言数。
- 多跳推理：固定问题集上的路径正确率、关键关系遗漏数和冲突识别数。
- 决策安全：当前 25 条回归、5 条事故、60 条留出继续报告 exact_match、unsafe_release、over_block；v2 必须保持 60/60 和 unsafe_release=0。
- 规则演进：v2 通过、v3 拒绝；新增候选规则必须给出改变原因、证据来源和门禁结果。
- 人工可用性：三名非开发者按固定任务完成率、找证据时间和解释是否能复核进行记录，原始评分表放入仓库。

消融优先比较去掉决定影响排序、去掉时间有效性检查、去掉图谱的效果。所有主要对照保持同一确定性判定器。若研究去掉判定器的风险，只在离线合成数据进行，结果单列。

预先登记以下工程验收目标，它们不是当前成绩或奖项门槛：

| 验收目标 | 判定方法 |
| --- | --- |
| 修订方法确有收益 | 主指标为固定审核预算下正确修复的受影响问题比例，同时守住总体正确率和回归约束；计时是成本指标，30% 提效不是预定事实或验收线 |
| 关键证据可定位 | 演示决定的关键依据 100% 定位到真实片段；完整测试报告证据正确率和漏引数，不能只计有无引用 |
| 变更处理有增益 | 同样标注预算下优于随机/不确定性抽样，若差异不稳定则撤回方法优势主张 |
| 没有以全拒绝作弊 | 报不安全批准、过量批准、误隔离、误拒绝及需要人工复核的比例，并报告可完成申请覆盖率 |
| 复现可交接 | 未参与开发的队员按锁定版本、数据哈希和 README 重跑，得到同一程序决定及可追踪模型日志 |

现有 unsafe_release 只数“应 DENY/ISOLATE 却 ALLOW/LIMIT”，未覆盖超出许可数量的 LIMIT；新评测须单列这类错误，不修改原基准定义来粉饰成绩。零观测错误不是零风险证明，不做事故减少率或全国推广收益外推。

## 现场演示脚本

中国总决赛官方安排为线上集中答辩，15 分钟展示、5 分钟问答。演示按一条可复现主线准备：

1. 先展示一张制造业研发实验室的领用申请，以及来自 PDF、表格和制度文档的证据卡片。
2. Nexent 运行资产认知 Skill，展示抽取出的实体、关系、来源页码和人工待审候选。
3. 检索 Skill 找到相关证据，图谱 Skill 展示“申请—批次—危害类别—位置—制度限制”的多跳路径。
4. MCP 调用确定性判定工具，屏幕原样展示决定 JSON、理由码和规则版本。
5. 加入尚未写死为开关的资料变更，展示候选 schema 差异、来源、审核与受影响问题；实际实现版本清单后才演示发布和回滚。v2/v3 只作独立教学基准，不能冒充此次资料生成的候选。
6. 展示一个证据冲突或缺失的案例进入人工复核。另一行业模板只在主场景完成、另有数据和独立验证后作为加分项；换行业的约束和金标准须重新审核。

答辩时要能回答：为什么不用直接问模型、事实冲突怎么办、证据来自哪里、规则谁批准、没有真实台账时结论有多大范围、换行业时哪些东西必须重做。
