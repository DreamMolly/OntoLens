## 本轮引用复核接口约定（2026-09-24）

- 扩展既有 evidence_rerank_jev 与 /api/evidence/jev，可选输入 citations，每项为 source_id、locator、quote、sha256；不新增 MCP 工具或 peiwu CLI 子命令。
- 程序先逐项核对已发布快照成员、原始文件哈希、定位和完整原文，任一项失败就不请求模型。不得按 limit 截断后漏掉坏引用。
- 字面来源匹配不等于语义正确。可选 Noul 分别判断支持与矛盾信号，只影响复核优先级，不产生或更改业务决定。
- 网页和 MCP 仅作本地核对，不能传入在线许可；只有 verify_jev.py --live 可请求，引用模式只使用固定的合成陈述与内置来源。
- 未配置密钥或未获在线许可时，JEV 仍是 unavailable；本地检查结果单独显示，不能冒充 JEV 推理。
- 模型辅助解释与业务裁决分离：工作台可按协议调用 `chat_completions`、`responses` 或 `messages`，只返回解释文本；协议响应不得写回 action、approved_quantity、reason_code 或快照。
- 修复重启自动授权合成资料的行为：内置种子显式允许外发，上传资料保持操作者选择；仅依据已有导入审计恢复被旧逻辑错误开启的权限，并记录修复事件。

## 信任边界

申请 JSON 进入规则卡和目录，由 checker 输出决定 JSON。门禁只比较版本，不修改当前版本。Nexent 拟负责调用、记录和解释，尚未接入。

决定 JSON 是唯一判定。技能正文、PPT 和口头解释如果与 JSON 不一致，以 JSON 为准，该次材料视为失败。

Nexent 不读取留出案例来修改规则。规则文件不得出现留出案例编号。

## 模块

- catalog：读取人员、化学品、批次、柜子，并检查引用。
- rules：读取一个版本的规则卡。
- checker：按 docs/02-rules.md 的顺序给出决定。
- evaluate：计算一致率和不安全放行。
- gate：判断候选版本能否替换基线。
- cli：decide、eval、promote 三个命令。

## 数据

- data/catalog.yaml：合成目录。
- data/rules/v1.yaml、v2.yaml、v3.yaml。
- data/cases/regression.yaml：v1 和 v2 必须完全一致。
- data/cases/incidents.yaml：记录 v1 的错误和 v2 的修正。
- data/cases/heldout.yaml：只评分，不参与改规则。

## 决定字段

- action：ALLOW、DENY、LIMIT、ISOLATE
- approved_quantity：数字或空
- reason_code：见规则文档
- rule_version：v1、v2 或 v3

## 以后的真实台账

接入真实资料需要同时核对数据含义和规则适用性，不能只替换 YAML。原 v1/v2/v3 和 H 集冻结；新映射与行业规则采用独立版本、人工核验和独立评价。

## 拟建的最小纵向流程

先只做一类变更：经审核的人员授权或制度生效期变化，定位哪些历史申请需要复核。它只是一项待验证业务示例，资料没有证实时不伪称真实场景。运行顺序为导入带定位的资料、生成候选、人工核验、按有效时间构建快照、查证据路径、调用确定性判定、显示可复核结果。

| 拟建工具 | 输入 | 输出与约束 |
| --- | --- | --- |
| evidence_lookup | 资料集版本、业务问题、来源过滤 | 文档哈希、定位、原文片段；不将检索结果直接当批准事实 |
| graph_query | 图谱版本、实体、申请时点、允许的路径模板 | 审核过的关系、有效期和来源；不暴露任意数据库写操作 |
| decision_check | 申请、已审核快照标识、规则版本 | 服务加载可信字段后调用现有判定器，原样返回决定及快照标识 |
| candidate_review | 候选版本、指定开发/验证资料 | 结构与回归报告，不修改 active_version；发布另需已批准记录 |

以上为 MCP 工具接口，不新增 peiwu CLI 子命令。工具数量取决于职责，不是评分指标。首轮只实现申请核验 Skill 的实际调用；导入和变更复核 Skill 在链路跑通后补齐。

## 拟建的状态与版本

编排状态使用 ready、needs_review、tool_error。后两者 decision 为空，界面显示“未作决定、需复核/重试”，它们不是第五、第六种业务决定，不伪装为 DENY 或 ALLOW。ready 时才返回 ALLOW、DENY、LIMIT、ISOLATE；这四种字段仍由程序产生。

数据、本体、规则、模型/提示配置分别记录版本与哈希。发布保存一份绑定这些版本的清单，在审核与检查通过后由负责人切换；历史决定永远指向原清单。回滚重新指向旧清单并记原因。这些版本管理能力尚未实现，当前 promote 通过不等于发布完成。

新增本体关系不自动生成可执行规则。能否映射到既有字段必须有人工审核的转换定义：例如仅在原规则语义确实一致时，把有效资格映射为人员 classes。新制度需要内核没有的运算时，标记不支持并停止决定；另写规则扩展规范和新测试后才开发，不能把任意新概念硬塞进旧字段。

## 拟建的失败行为与资源范围

文档正文只作为数据，不能指示工具执行、改写规则或改变授权。模型没有发布和真实出库权限。对缺失来源、单位不明、失效资料、工具超时和越权更新分别保留错误记录；演示不得用缓存伪装为实时调用。

首轮保留 Nexent 原生知识库和模型连接，项目侧优先采用文件证据账本与一个轻量图实现（RDFLib + SHACL 或等价方案）。先测小样本文档解析；不同时引入另一个完整 RAG 服务、图数据库集群和本地大模型。具体解析器和图存储通过样例兼容性测试后锁定版本。
