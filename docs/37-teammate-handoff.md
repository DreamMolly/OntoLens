状态日期：2026-10-09。本文件记录规划路径、已完成/待完成条件和可拓展项，不安排人员任务。启动步骤见[业务部署](38-operational-deployment.md)和[README](../README.md)。

## 验证证据的口径

后端专项68、账户专项45、旧新组合105和6条HTTP流程各是不同且部分重叠的范围，**不能相加为完整测试数**。命名迁移后正式全量结果为464 passed、七阶段全部exit 0、158个输入指纹匹配；日志快照见 `../artifacts/source-validation/20261009-094214-e5337f3f/`。356与456是较早的软件阶段基线。

资料import声明只表示操作者提供用途和授权说明；schema/hash/规范化一致性检查不证明文件真实或专业合规。登录身份绑定增强了操作者归属，账户审计仍是本地记录，不是独立专业审核或防篡改认证。

10-08 Nexent历史运行收据时间为12:02:51–12:04:45 UTC，7工具实际调用通过，Agent2无工具生成，Agent1当次模型工具编排后返回合成ALLOW六关系；这不是10-09的 `gpt-6-sol` 模型链路结果。10-09配置收据记录 `gpt-6-sol` Agent绑定，当前容器收据记录30项检查及Agent2无工具解释通过。宿主Web 13000/内部3000。Linux新机冷启动、长期运行与真实业务资料另待验证。

真实设备、实际读屏和浏览器UI缩放与Playwright模拟视口/CSS zoom分别报告；界面美观、按钮通过不能推导工业安全效果。

## 可操作演练

1. 用新业务数据库和账户启动8768；确认登录和 `operational_empty`，没有demo-initial事实。
2. 在原始资料导入六台账，查看原始/规范化来源、输入错误、候选检查与影响预览。
3. 管理员确认发布实际候选；并发active变化时拒绝覆盖。operator填写申请并核验。
4. 打开实际关系原文，改申请立即dirty；查看历史再返回保持当前草稿，导出指向正确run。
5. reviewer追加补件/复核，引用默认未选，身份来自已登录账户；原决定不改变。
6. 可选模型/Nexent/JEV分别显示当前调用范围与状态；私有原文不外发，失败不改判。
7. 演示brand旁折叠图标、边缘拖动/键盘调宽、窄屏和原文检查器；不要重新加入底部宽度按钮/冗余卡。
8. 导出后离线重算，核对版本与原字节；最后退出登录。演练资料性质必须明示，不能用演练当实际行业结果。

## 可拓展方向

| 方向 | 可继续做的内容 | 保留边界 |
| --- | --- | --- |
| 比赛前端体验 | 密度/层级、清楚错误、触摸/读屏/缩放实测、逐项交互证据 | 不用假KPI、假保存、假模型打字 |
| 真实台账适配 | 字段映射、日期单位、版本预检、实际授权与备份恢复 | 来源声明不自动成为专业审核 |
| 账户部署 | 更细资料访问、组织隔离、外部身份接入、恢复与持续运行 | 当前四角色是操作级权限，不冒充多租户ACL |
| 检索与模型 | 独立无答案/错误条款/长原文评测，获准JEV对照、调用延迟成本 | 解释辅助，确定性内核继续拥有决定 |
| 平台复现 | 当前Agent展示、新环境安装、容器恢复与工具失败诊断 | observed_at新探测，不用旧ready |
| 审计可信性 | 已明确部署需求后的签名、备份、操作溯源与完整性保护 | 现有本地hash/追加记录不等于不可篡改 |

规划按功能与验收阶段组织。当前主实现和新配置使用 OntoLens；旧 Python 入口、既有 Nexent 机器标识及冻结导出协议的兼容范围见[品牌与兼容说明](39-brand-compatibility.md)。源码发布排除账户、运行数据、私有台账和凭证。
