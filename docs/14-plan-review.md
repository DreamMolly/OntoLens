# OntoLens 规划审查

软件建设与研究主张分别验收。当前完整规划路径见[里程碑](37-teammate-handoff.md)，方法假设见[研究问题](10-research-question-card.md)，对照规则见[评测协议](13-evaluation-protocol.md)。

## 需要成立的条件

| 维度 | 当前基础 | 验收条件 |
| --- | --- | --- |
| 业务问题 | 台账核对、制度变更和历史追溯的可操作流程 | 经授权真实任务、现用字段、领域适用 |
| 软件闭环 | 来源、候选、版本、核验、复核、导出 | 失败与恢复组合、权限及独立环境 |
| 平台与模型 | Nexent 七工具、Skill 与受控解释 | 当前真实调用轨迹、错误记录、模型限制 |
| 方法贡献 | 带来源候选、影响预览和冻结工程夹具 | 公平基线、相同人工预算、独立标签与消融 |
| 展示体验 | D1.1 首页、侧栏与关系/原文联动 | 真实设备、读屏、任务效率和代码讲解 |

不将额外组件数量视为创新收益。目录或表连接能解决的任务应与图谱方案公平比较，不能仅凭确定性规则胜过弱基线证明方法优势。

## 可验证主张

一条申请的程序决定绑定原文、快照与规则，能离线重算；候选先检查，发布受权限与并发保护；模型只检索、复核和解释。这些是当前工程贡献，真实专业适用与行业收益仍需外部证据。

领域本体更新区别于普通事实录入。新增关系或类型要有制度依据、允许的转换与审核，不把固定 v2 开关或拒绝坏候选称作自主学习。

## 资源与范围

优先实测当前已授权环境，记录内存、CPU、模型请求数、输入/输出量、延迟、成本与重试。设备满足上游最低要求不等于业务系统长期稳定；接口测试、模型健康检查与实际 Agent 运行分别报告。

先完成一类明确任务和一组可复核资料，再扩充规模或行业模板。没有来源、标签或授权时缩小结论，继续独立软件与公开资料工作。新增组件应减轻真实任务复杂度，不将缓存或模拟结果当实时成功。

## 未关闭条件

真实任务与专业适用、独立人工标签、方法收益、新机/恢复、长期运行和正式材料仍需验证。计划和文档不能代替这些事实，软件能部署也不能直接保证国奖。
