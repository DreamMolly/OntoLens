# Nexent 边界

Nexent 是平台，不是本项目的作品。技能文件只规定调用方式。

## 必须遵守

1. 收到申请后运行 python -m peiwu decide。
2. 把命令打印的 JSON 原样放进回复。
3. 不把打回改成放行，不改批准数量，不编造理由码。
4. 可以解释理由码。解释和 JSON 冲突时，承认 JSON。
5. 要改规则时复制新版本，先运行 python -m peiwu promote。失败就保持原版本。
6. 不打开 data/cases/heldout.yaml 来决定怎么改规则。

## 不能做

- 不能直接用自然语言回答“可以领”。
- 不能查完资料后自己算一个新决定。
- 不能把没有命令输出支撑的留出成绩写进申报书。

## 演示顺序

同一命令连续运行两次时，打印的 JSON 必须逐字相同。

1. v1 对一条事故申请放行。
2. v2 对同一条申请打回。
3. 升版命令显示 v2 通过、v3 失败。
4. 再跑一次决定命令，证明屏幕结论就是程序输出。

当前只放置 skills/peiwu/SKILL.md；它不是 Nexent 导出配置，也不是已完成平台集成的证据。

## 新规划中的平台验收

官方支持本地下载 Nexent，安装开源平台不要求先有华为账号。部署机器、容器服务、模型端点及费用授权仍需队员落实。本轮不安装或购买服务。

首个验收只要求一条真实链路：在 Nexent 中发起申请核验，依次调用证据检索、图查询和决定工具。保存 Nexent 的版本/提交标识、无密钥配置、模型标识、Skill 配置、工具调用输入输出和延迟。返回决定必须来自程序；资料缺失和超时则按架构进入非决定状态。

实际运行后才扩展资产导入和变更复核 Skill。逐字一致只适用于相同快照的确定性决定，不能要求模型生成的所有解释逐字一致；解释需检查来源正确和不改判。离线回放须明确标“录制回放”，不能作为平台在线验收证据。

## 报名后配置包

报名已完成。可导入的模板位于 nexent/，使用顺序和依赖清单见 docs/17-nexent-package.md。Nexent 官方当前文档支持 Agent JSON/ZIP 导入、Skill 绑定和远程/容器化 MCP 服务；本项目模板把模型 ID 和容器令牌保留为占位符，必须由队员在目标环境补齐。
