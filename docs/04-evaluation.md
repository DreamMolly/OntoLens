# 评测和升版

此页描述冻结教学原型。新的端到端与本体实验按 [评测协议](13-evaluation-protocol.md) 执行，不混用成绩。

## 三套案例

- 回归：授权正确、柜子错误、停权、过期、破损、超过上限、库存不足、非法数量、未知编号，以及不会触发冲突的当天领用。v1 和 v2 的输出必须相同。
- 事故：v1 会放过、v2 会拦住的同一天冲突。至少覆盖易燃对氧化剂、酸对碱。
- 留出：另一批人员或数量组合。修改 v2 时不打开这个文件。

案例都是手工组合，不用复制凑数。留出集在 2026-09-22 从 12 条种子扩到 60 条，早于原定的 2026-11-09。扩写时没有修改 v1、v2、v3。目录只新增 lot_eth_tie 和 lot_tox_tie，用来覆盖上限与库存一样紧的情况；原有批次没有改。当天实测 v2 的 exact_match 为 60、unsafe_release 为 0，v1 的 unsafe_release 为 13。

H01–H60 后续已被开发者检查，继续作为冻结合成基准；文件名保留，但不能称为独立行业盲测。60/60 表示符合手工期望值，不是 AI 准确率或真实安全率。

## 指标

每一套案例报告：

- exact_match：决定、批准数量、理由码都与期望相同。
- unsafe_release：期望是打回或隔离，实际却放行或限量。
- over_block：期望是放行，实际却打回或隔离。

限量数量不符只算 exact_match 失败，不另造一个模型分数。模型输出不进入这些数字。

## 门禁

候选版本同时满足下面四条才通过：

1. 回归集上，决定、批准数量、理由码与基线完全相同。
2. 事故集上，候选与 gold_v2 完全相同。
3. 留出集上，候选与 gold 完全相同。
4. 留出集的 unsafe_release 不高于基线。

事故集不要求候选与基线相同，否则已知错误就不能修。

v2 对 v1 应该通过。v3 让学生一律打回，回归集会变化，必须失败。

## 防泄漏

- 规则卡只有类别、比例和开关，没有案例编号。
- 测试检查 v1 和 v2 的文本不含留出编号前缀 H。
- eval 可以读留出集。改规则的记录里禁止把留出结果写回规则卡。

禁写案例编号只是一项局部检查，不能防住来源、语义或提示层面的泄漏。新实验必须按来源家族隔离最终测试，不靠编号检查宣称“无泄漏”。
