# 评测协议

状态：规划。指标、基线和样本划分在实验前冻结；运行结果进入原始日志，不用模型自评替代人工标签。

## 研究对象

评测的是“制度或资产资料变更后，系统发现、复核并更新受影响知识与决策路径”的能力。不是评测大模型能否写出流畅解释，也不是宣称自动批准或替代专业安全职责。

当前仓库额外提供 data/evaluation/asset-recognition.yaml 和 scripts/evaluate_assets.py，作为目录资产标识、明确授权句式和有效期 schema 候选的合成回归夹具。它只能检查实现是否回归，不能作为真实行业准确率、低资源算法优越性或标准对齐结果。

## 基线

| 系统 | 保持相同的条件 | 检验什么 |
| --- | --- | --- |
| 人工字段表 + 表连接 + 静态规则 | 同一资料、同一制度、同一确定性判定器 | 不用图谱时的维护成本与正确率 |
| 文档检索增强 + 判定器 | 同一模型、相同资料范围、提示预算、人工预算 | 普通文本检索是否已足够 |
| 固定图谱 + 判定器 | 同一模型、同一图谱初始状态和判定器 | 本体增量更新是否带来收益 |
| 每次全量重建本体 + 同一审核预算 | 同一初始资料、候选模型、时间预算和判定器 | 增量方式相对可用更新方案的代价与质量 |
| 配伍完整方案 | 同一资料、人工预算和判定器 | 按决定影响排序的审核与可追溯更新 |

直接问模型只能作为额外演示，不作为主要赢家基线。每个模型型基线重复运行至少 3 次，记录模型/提示版本、随机设置、延迟、失败和成本。

固定本体方案不能被人为剥夺新资料，允许它用通用关系或人工映射处理；不能用“它无法新增 schema”作为唯一胜因。人工字段基线也允许读新资料和维护映射，初始化及维护时间均计入成本。

## 分开两个实验

实验 A 固定已审核字段、来源和规则，只比候选选择、本体更新与版本影响分析。实验 B 使用原 PDF、表格和扫描资料，从抽取到最终决定全链路执行。不得把实验 A 的成绩写成 OCR/模型抽取后的端到端成绩。

每个实验均包含不变案例、仅事实变化、本体结构变化和资料冲突；各类分别统计。对于本体结构变化，金标准要列出新增/修订类型、端点、定义、约束及映射，不能只列多出来的实体三元组。

## 可实现的候选选择协议

首轮所有自动方法共享同一个冻结的候选列表，每项有来源、schema 差异和固定业务问题集，避免把候选生成质量混入排序收益。候选无法映射到支持的语义时标 unsupported，不让模型编造执行逻辑。

完整方法先做结构检查，再在不发布的沙盒中试算候选，记录会改变答案/决定的开发路径数量、会使原路径失去证据的数量、来源冲突标志和仍未覆盖的关系类型。按“需复核的冲突、受影响路径数、未覆盖类型、稳定候选 ID”排序；相同关系族每轮先取一个，避免别名重复占满人工预算。这是可检验的启发式，不预称新算法。

同一候选集上对比随机、仅冲突优先、抽取不一致优先三种排序。抽取不一致以多次抽取的分歧定义，不能比较未经校准的模型自报置信度。分别测 5/10/20 个审核候选的预算；若候选不足则缩小并报告实际数量，不人工扩充凑数。初始 schema 种子数量、候选审核预算、专家耗时是三个不同变量，单独记录。

影响路径只来自预先登记的开发业务问题与可读图结构，绝不能读盲测标签。审核人时间从看来源开始计到批准/拒绝结束；AI 自己认可自己的候选不算人工审核。

## 核心指标

### 资产与图谱

- 实体规范化准确率：正确规范化实体数除以应规范化实体数。
- 关系 Precision、Recall、F1：与人工金标准比对，分开报告关系类型。
- 来源定位正确率：关键事实的定位同时正确文件、页码或单元格/图片框和支持片段。
- 冲突发现率：已标注冲突中被明确标为待复核的比例；同时报告误报数。

### 跨文档决策

- 路径正确率：预期关系路径被正确找到且不包含关键错误边的比例。
- 证据完整率：一个决定的全部关键事实均有正确来源定位的比例。
- 可完成申请覆盖率：系统能够给出可执行决定的比例；证据缺失或冲突时转人工复核不计为放行。
- 安全错误：不安全批准、超量批准、误拒绝、误隔离和错误限量分别计数。现有 unsafe_release 保持原定义，不能替代这五类统计。

当前确定性评测器会同时输出 `error_breakdown`、`action_matrix` 和逐条
`failures[].mismatch`。其中 `unsafe_release` 保留历史定义（期望
`DENY/ISOLATE` 却得到 `ALLOW/LIMIT`），`over_issue` 单独统计实际批准数量
高于金标准的情况，避免一个“动作相同”的 LIMIT 掩盖超量批准；
`over_block` 统计应放行却拒绝/隔离，`under_issue` 统计动作仍为
`ALLOW/LIMIT` 但批准数量低于金标准。报告还拆分动作、理由码和批准数量
三类不一致。它们都是合成回归诊断指标，不是行业安全率。

可用以下命令生成带输入文件 SHA-256、逐套评测和 v2/v3 gate 的可审计收据：

```powershell
.venv/Scripts/python.exe scripts/generate_synthetic_evaluation_report.py
```

默认输出 `artifacts/synthetic-evaluation-report.json`。收据的
`scope.mode=synthetic_demo` 和 `scope.claim_boundary` 必须随申报材料保留；
没有真实脱敏资料、领域金标准和独立盲测时，不把其中的 exact match 写成
行业准确率或事故减少率。

另外，`scripts/generate_counterfactual_evaluation_report.py` 会运行独立的
`data/evaluation/counterfactuals.yaml` 变形夹具。它逐案记录输入哈希、唯一变更路径、
基础/变体结果和 `needs_review` 边界，用来检查决定是否只随指定事实变化；该报告仍属于
`synthetic_demo`，不替代真实资料或专业审核。

### 低资源更新与人工成本

- 每个正确获批关系的人工复核分钟数，中位数和四分位距。
- 在固定审核预算下的新增正确关系数、受影响路径正确率和版本回归数。
- 变更影响定位时间、局部重算与全量重算的输出一致性。

## 比较与报告

每个方案使用同一数据划分、同一人工预算和同一判定器。资料包数量小时报告每个包的原始值和置信区间或区间估计，不只给均值。若完整方案不稳定优于最强基线，结论写为“未观察到明确优势”，并保留失败案例。

主指标预先指定为“固定审核预算下，正确修复的受影响业务问题比例”；总体全部问题正确率、未受影响问题回归数和安全错误是共同约束。人工复核分钟数为成本指标，不能只选相对最好的一项。约 30% 提效只能是开发愿望，不是通过标准；正式通过标准要在开发预实验后、盲测前锁定，不根据盲测改阈值。

计时对照采用平衡任务分配：参与者不反复看同一个问题的标准答案后再测另一方法；初次整理表格的成本和维护变更的成本分开报告。领域正确性审核与三人界面可用性测试分开，三名非专家不能替代领域金标准。

统计单位是独立资料包/来源组，不是同一包的三道问题或同一模型的三次重复。样本足够时在组级做配对区间估计；若只有两个开发包，只报告原始观察，不称显著提升。时间切分必须保证回答历史请求时看不到未来有效的资料版本。

单列输入缺失、来源伪指令、未知单位、版本冲突、过期授权、工具超时以及未授权发布的测试。needs_review/tool_error 不算正确业务决定，但若金标准就是“无法确定需人工复核”，应计入正确拒答；同时报告决定覆盖率，防止全转人工获得虚假高安全分。

人工可用性单独做三名非开发者的小规模任务：定位一条决定依据、识别一个冲突、判断是否需要人工复核。记录完成率、耗时和解释可复核性；这只说明演示可用性，不代表大规模用户研究。

## 消融

主要消融保持同一确定性判定器：

1. 去掉“受影响决定优先”排序，改为随机审核。
2. 去掉制度生效时间和版本冲突检查。
3. 去掉图谱关系，只使用文档检索。

若研究去掉确定性门的风险，只能在离线合成资料上运行，并单列结果。不能在真实流程中让模型单独做安全放行。

## 发布门槛

新知识或规则版本必须：来源完整、领域审核完成、结构约束通过、开发/验证集评测完成、冻结原规则内核回归通过。最终盲测只在方案冻结后运行一次；若结果失败，记录失败而非把盲测加入调参循环。

展示和申报中每一个数字都要能指向命令、原始日志、数据版本和指标定义。没有真实数据时不使用“行业准确率”“降本增效”“事故减少”等表述。
